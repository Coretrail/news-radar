# Security policy / Política de segurança

## Reporting a vulnerability

Do not report vulnerabilities, exploit details, credentials or administrator setup links in public issues or pull requests. If this repository has GitHub private vulnerability reporting enabled, use **Security → Advisories → Report a vulnerability** to contact its maintainers privately. Check that the report is private before submitting.

If that option is unavailable, use a private contact channel explicitly published by the repository owner. This template does not invent a security email address or guarantee a private reporting service. Until you have a verified private channel, keep sensitive details out of public discussions.

Include the affected revision, deployment method, impact and a minimal reproduction using synthetic data. Redact secrets and personal/private infrastructure details. Do not access or modify systems you do not own to demonstrate an issue.

This is a reusable template; each fork's owner is responsible for its deployment and security response. There is no promised response time or long-term support window. Use the latest reviewed release of your chosen repository, review security updates and test changes before deploying.

The reading dashboard is unauthenticated; administrator login protects administration. See the [deployment security guide](docs/en/security.md) for network access, TLS, secret handling and maintenance.

## Comunicar uma vulnerabilidade

Não comunique vulnerabilidades, detalhes de exploração, credenciais ou endereços de configuração administrativa em issues ou pull requests públicas. Se o repositório tiver comunicação privada de vulnerabilidades no GitHub, use **Security → Advisories → Report a vulnerability** para contactar os responsáveis em privado. Confirme a privacidade antes de enviar.

Se essa opção não estiver disponível, use um canal privado explicitamente publicado pelo proprietário do repositório. Este template não inventa um email de segurança nem garante um serviço de comunicação privada. Até obter um canal privado verificado, mantenha os detalhes sensíveis fora das discussões públicas.

Indique a revisão afetada, método de instalação, impacto e uma reprodução mínima com dados sintéticos. Oculte segredos e detalhes de pessoas ou infraestrutura privada. Não aceda nem altere sistemas alheios para demonstrar um problema.

Este é um template reutilizável; cada proprietário de um fork responde pela sua instalação e segurança. Não se promete um prazo de resposta nem um período de suporte prolongado. Use a versão revista mais recente do repositório escolhido, acompanhe atualizações de segurança e teste alterações antes de instalar.

O painel de leitura não tem autenticação; o login administrativo protege a administração. Consulte o [guia de segurança](docs/pt/security.md) para acesso de rede, TLS, segredos e manutenção.
